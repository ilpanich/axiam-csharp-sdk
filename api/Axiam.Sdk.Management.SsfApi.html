Remarks

A REPLACEMENT, not a patch: what the body does not carry is not preserved (a member left unset is omitted from the wire, not sent as null), so read the current value first and carry over the parts you mean to keep (§27.4 rule 5).

The three meanings of events_requested on an update (§32.2, contract 1.62) — keep them apart: absent *resets* the stream to every event of events_allowed (as on create), widening what the receiver narrowed; [] is stored as the receiver's "none" (it does not widen, and the stream carries nothing); a list is stored as given and refused (400) if any entry is outside events_allowed. A raw API client, with no SDK, is bound by the same meaning: an events_requested left out of the PUT resets the stream. An omitted optional member takes its default on every write, including an update: description, endpoint_url and status_reason null, subject_format iss_sub, status enabled, clear_authorization_header false — except authorization_header, which absent keeps the stored one — unless the update moves endpoint_url to another scheme, host or port while a header is stored: then it must carry authorization_header again or clear_authorization_header: true, else 400 (§32.3 rule 5). Contract 1.61: expected_updated_at (the updated_at string you read, sent as given; null or unset is "none" and the key is omitted) makes the update conditional on that version, and an update overtaken by a write since — the receiver's own included — is 409 (ConflictError, never retried): read the stream again. An edit therefore sends back the events_requested and expected_updated_at it read, with events_requested cut to the new events_allowed when the ceiling is lowered. Use stream.ToInput(new SsfStreamChanges { ... }), the change-taking form, which does all three; stream.ToInput() is the plain converter and leaves the cut to you.

Not retried: §27.4 rule 8 makes every write on this surface single-shot, including the ones that look idempotent.
