Remarks

No conversion carries a secret: the read types have none (§29.5, §30.2, §31.2, §32.5), so BindSecret, AuthorizationHeader and Credential come back absent — which, on the update that follows, means "keep the stored one" (subject to the connection-move rules each section states). Set one with a with-expression when the write moves the connection.

Remarks

The version is the server's own string when the target came from this SDK's ScimTargets calls, because the server compares it for equality at nanosecond precision and DateTimeOffset keeps 100 ns. For a target built any other way it is UpdatedAt in the round-trip format. Set ExpectedUpdatedAt to null with a with-expression for a last-writer-wins replacement.

Remarks

Prefer ToInput(SsfStream, SsfStreamChanges) when the edit changes the stream. This converter cannot know that you are about to lower the ceiling, so cutting events_requested to the new events_allowed is the caller's duty wherever a body is built another way (a with-expression over this result, an object initializer): a requested list left outside the new ceiling is 400, and one left out altogether resets the stream to every event of events_allowed, widening what the receiver narrowed. Those are the three meanings of events_requested on an update (§32.2): absent resets, [] is the receiver's "none", a list is stored as given. An update conditional on the expected_updated_at read is 409 (ConflictError, never retried) once the stream has been written since, the receiver's own writes included: read again and decide again.

An events_requested of [] stays []: omitting it would reset the stream. The version is the server's own string when the stream came from this SDK's Ssf calls (§32.2: never parsed and rendered again, because the comparison is of the instant); for a stream built any other way it is UpdatedAt in the round-trip format. Set ExpectedUpdatedAt to null (the key is then left out, and null is never sent) to replace whatever is stored.

Examples

SsfStream stream = await client.Ssf.GetStreamAsync(id);
await client.Ssf.UpdateStreamAsync(id, stream.ToInput(new SsfStreamChanges
{
    EventsAllowed = new[] { SsfEventType.SessionRevoked },   // lower the ceiling
}));

Remarks

What the body carries, and why each point is a rule rather than a convenience:

  • events_requested, as read. An update that omits it resets the stream to every event of events_allowed, widening what the receiver narrowed. The read list goes back as it was; an empty list (the receiver's "none") goes back as [] and is never omitted.
  • Cut to the new ceiling. When changes lowers events_allowed and does not name events_requested, the requested list becomes the entries of the read list that are in the new ceiling, in their order (a request outside the ceiling is 400). An EventsRequested named in changes is sent as given: the server judges it. An entry this SDK decoded as Unknown cannot be shown to be in the new ceiling and is dropped by the cut.
  • expected_updated_at, as read. The updated_at string of the stream you read, byte for byte (§32.2). The update then lands only on the version you read, and a write made since, the receiver's own included, answers 409 (ConflictError, never retried): read again and decide again. An ExpectedUpdatedAt of Null in changes is "none": the key is left out and null is never sent.

authorization_header and clear_authorization_header are absent unless changes sets them: absent keeps the stored header. This is the form to use; ToInput(SsfStream) is the plain converter, whose documentation names the caller's duty.
