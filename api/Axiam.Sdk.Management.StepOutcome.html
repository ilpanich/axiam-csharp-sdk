Message string

The server's explanation, present only on Failed.

RestoreSucceeded bool?

CONTRACT.md §27.6.1 item 2 (contract 1.51): a role-binding UPDATE is unassign then assign, not atomic. When the assign half fails, the SDK re-assigns the PREVIOUS binding (same resource, same inherit, same tenant_scope) before reporting the step failed. null for every step that is not this kind of failure; true when the restore succeeded (the subject still holds its old binding); false when it also failed (the subject holds NEITHER the old nor the new binding — Message says so).

CreatedServiceAccount ServiceAccountCreatedResponse

CONTRACT.md §27.5 rule 5 (contract 1.51): on a Created outcome for a ServiceAccountSpec, the response apply received — client_secret included, and the ONLY time it is ever returned. Kept here even when a LATER action of the same apply fails (§27.6 rule 7's "every attempted action's outcome"), because it is the only place this credential is retrievable. null for every other step.

RestoreError string

CONTRACT 1.52 N6.3 (C-12): the restore's OWN error, reported as data rather than only folded into Message's prose — a caller inspecting the outcome programmatically can read it without parsing text. null whenever RestoreSucceeded is null or true; set alongside RestoreSucceeded: false.
