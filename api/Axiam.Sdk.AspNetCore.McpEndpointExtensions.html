ServeProtectedResourceMetadata(IEndpointRouteBuilder, ProtectedResourceMetadata, AxiamOptions?)

Registers the one GET route that serves metadata's document, at the path MetadataPath names, and returns metadata unchanged so it can be chained.

public static IEndpointRouteBuilder ServeProtectedResourceMetadata(this IEndpointRouteBuilder endpoints, ProtectedResourceMetadata metadata, AxiamOptions? guard = null)

Parameters

endpoints IEndpointRouteBuilder

The application's root endpoint route builder. Register on the root, not a router mounted under a prefix: a prefixed router would serve the document at a path the derived URL does not name.

metadata ProtectedResourceMetadata

The value ProtectedResourceMetadata(ProtectedResourceMetadataOptions) returned.

guard AxiamOptions

Optionally, the options the §10 guard was built from. Passing it applies §28.5 rule 3's cross-check: the guard's ResourceMetadataUrl must equal metadata's MetadataUrl and its ExpectedAudience must equal metadata's Document.Resource — both plain string equality (RFC 3986 §6.2.1), no normalisation. Omit it where the guard is configured in a different process; nothing can be checked from here then, and the operator configures both from the one MetadataUrl constant instead.

Returns

IEndpointRouteBuilder

endpoints, for chaining.

Remarks

The path is derived, not chosen, and exactly one route is registered (CONTRACT.md §28.3): a deployment fronting several resources calls this once per resource, and the derived paths cannot collide because each comes from its own resource.

The response is 200 with Content-Type: application/json, the document as its body, Cache-Control: public, max-age=3600 and Access-Control-Allow-Origin: * (never Access-Control-Allow-Credentials, which would ask a browser to attach a user's cookies to a request that has no use for them) — the CORS header is safe precisely because the response is identical for every caller. Nothing is read from the request, so there is no per-caller content and no Set-Cookie.

.AllowAnonymous() is applied explicitly so the document still answers unauthenticated even in an application that has configured a global authorization fallback policy (§28.3 rule 2). Where the §10 guard is applied globally via AxiamAuthMiddleware, that middleware separately exempts this exact path from its own credential handling, derived from the same ResourceMetadataUrl — so the route works whichever order the middleware and this call are registered in.

Exceptions

ValidationError

guard is given and its ResourceMetadataUrl is not exactly metadata's MetadataUrl, or its ExpectedAudience is not exactly metadata's Document.Resource.
