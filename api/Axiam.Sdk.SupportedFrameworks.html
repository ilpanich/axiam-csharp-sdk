Remarks

NuGet already enforces the lower bound at restore time — the package ships a lib/ folder per target framework and refuses to install into a project targeting anything older. What it does not tell you is the *upper* end: a package with a lib/net8.0 folder installs happily into a net10.0 project and runs there under roll-forward, whether or not anybody ever built or tested it on that runtime.

These values name both ends, so a deployment preflight or a startup assertion can report which of them the running process is actually on. See examples/VersionCompatibility.

VersionPolicyTests asserts these against the <TargetFrameworks> in Axiam.Sdk.csproj and against the CI workflow, so they cannot drift from what is actually built.
