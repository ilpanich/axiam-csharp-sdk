Remarks

Everything here is pure: no I/O, no client state, no network. The two HTTP calls and the policy around them live in AxiamClient.LoginSrpAsync.

H is SHA-256 throughout. RFC 5054 specifies SHA-1; AXIAM does not use SHA-1 anywhere and does not start here.

DeriveX(string, char[], byte[], SrpKdfParams)

x = KDF(identity ":" password, salt), as raw bytes (§23.3 rule 3).

Parameters

Returns

Remarks

RFC 5054's bare-hash x would make a leaked verifier cheaper to attack offline than the Argon2id hashes AXIAM stores today, which would make adopting SRP a net regression at rest — so the KDF is memory-hard, and the server dictates which one per exchange.

identity is the one the server named in the challenge, never what the human typed (§23.3 rule 2).

Exceptions

NetworkError

The named KDF is not one this SDK implements.

Remarks

Every SRP quantity is unsigned. Reading one with .NET's default little-endian, signed interpretation would produce a negative value whenever the top bit happened to be set, and every modular operation after that would be computed in the wrong ring.
