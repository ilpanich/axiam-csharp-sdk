Verifies the X-Axiam-Signature HMAC-SHA256 header AXIAM attaches to every webhook delivery (CONTRACT.md §13, T-145). Mirrors the server's signer (crates/axiam-api-rest/src/webhook.rs's compute_signature_v2): the MAC covers the ASCII string <t>.<raw_body>, keyed with the webhook secret's raw UTF-8 bytes.

Parameters

secret Sensitive<string>

The webhook's plaintext signing secret (CONTRACT.md §7 Sensitive<T>). Its raw UTF-8 bytes are the HMAC key. Wrap a bare string with Wrap(T).

signatureHeader string

The raw, unparsed X-Axiam-Signature header value — t=<unix_seconds>,v1=<hex>, optionally with multiple v1 entries during secret rotation.

body ReadOnlySpan<byte>

The exact raw bytes received off the wire, before any JSON parsing. Re-serializing a parsed body (different key order/whitespace) changes these bytes and breaks the MAC — callers MUST buffer and pass the untouched request body. In ASP.NET Core this means enabling HttpRequest.EnableBuffering() (or reading the body stream directly) before any model binder has had a chance to parse and re-serialize it.

tolerance TimeSpan?

The freshness window; null or a non-positive value falls back to DefaultTolerance (300 seconds). Rejects a t= more than this far in the past OR the future — a two-sided check, so a future-dated timestamp is rejected just like a stale one (clock-skew abuse).

timeProvider TimeProvider

Test/injection seam for "now"; defaults to System. Pass a fake TimeProvider to deterministically exercise the freshness check.

Returns

WebhookEvent

The verified, parsed WebhookEvent.

Exceptions

WebhookVerificationException

The header is malformed (no v1, more than one t, non-numeric t, or empty), no supplied v1 matches the recomputed MAC, or t falls outside the freshness tolerance. The exception message is always a fixed, generic reason string — never the expected signature or the secret (CONTRACT.md §13.3 rule 6).
