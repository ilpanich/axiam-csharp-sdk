Remarks

A SUB-TYPE of AuthzError. §2 already maps 409 there as "resource-level access denied", and CONTRACT.md §27.4 rule 7 keeps that mapping rather than re-deciding it — the sub-type exists to give the caller something to act on, not to move the status.

Never retried: a 409 is the server telling the truth, not a transient fault, and repeating the request cannot change it (§27.4 rule 8).

Remarks

CONTRACT.md §36.4 (contract 1.62): every 409 of the twelve network operations says which in reason_code — stale_version, strands_profile, has_children, site_gone, duplicate_name, duplicate_vlan, duplicate_rank, profile_exists or other (§36.3 rule 2). The vocabulary is open: a value this SDK has never seen is surfaced as the string the server sent, and a caller treats it as a conflict whose Message is for a human. Branch on this member, never on the message, which an SDK must not parse.

It is not the reason of an authorization decision (§3), which is a human string. The error slug (conflict or already_exists) maps to ConflictError either way and is not exposed.
