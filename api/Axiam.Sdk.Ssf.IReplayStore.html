Remembers the jtis already accepted, for §32.7 step 9. Pluggable so a receiver running several instances can share one store.

public interface IReplayStore

Remarks

A store has three answers (CONTRACT.md §34.2 P4): first sighting (true), already seen (false), and cannot answer — which is an exception, never false. A store that cannot answer gives no verdict: the receiver treats the SET as unjudged, raises a NetworkError with no reason code from VerifySetAsync(string, CancellationToken), and PollAsync(string, SsfPollOptions?, CancellationToken) records nothing for it and leaves it out of both Events and Refused, so you do not acknowledge it and the transmitter offers it again. Answering false because the backing database is down would instead report the event as replayed — which §34.2 P2 has you acknowledge — and an event that was never processed would be lost.
