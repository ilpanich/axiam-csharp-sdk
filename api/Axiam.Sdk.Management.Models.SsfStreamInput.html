Remarks

This body REPLACES rather than patches (§27.4 rule 5): what you do not carry over from a prior read is not preserved, it is overwritten. audience, delivery_method, events_allowed, receiver_client_id are required, so forgetting one is a compile error; an optional property you leave unset is omitted from the wire, and the server then applies its default rather than keeping the stored value, except where the operation documents otherwise. Read first, with-expression the parts you mean to keep, write back.

A subset of events_allowed; absent means all of them. The receiver may narrow it later, never widen it. ExpectedUpdatedAt

The updated_at of the stream as the client read it (R1W2-03, T-406). Update only; create ignores it. When present, the replacement lands only if the stream still has that version, else 409 (reload and retry): a pause or a narrowing the receiver made after the form was read is not silently reverted. When absent the replacement is conditional on the version the server reads during the request — an old client keeps that behaviour, and the console always sends it.
