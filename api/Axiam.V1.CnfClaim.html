RFC 7800 confirmation claim (X5.1). Either, both or neither member may be set; a claim with NEITHER set names a confirmation method this server version does not implement.

The consumer rule is the same one SDK contract §10.1 rule 9 makes normative, and it is the whole reason this message exists: a confirmation the consumer cannot check MUST be refused, never read as "unconstrained". Two members set is a CONJUNCTION — both must hold.
