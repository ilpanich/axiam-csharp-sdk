Authentication failure: wrong credentials, expired session, MFA failure, a 401 on refresh, an RFC 6749 OAuth2 protocol error (CONTRACT.md §12.3 rule 3 — see OAuthProtocolError), or a §12.4 ID-token validation failure (CONTRACT.md §2, D-12). Always constructed via ErrorMapper for the pre-existing REST/gRPC taxonomy, or directly for the §12 additions, so no code path drifts from the error taxonomy.

Remarks

Deliberately NOT sealed (CONTRACT.md §2 permits "language-idiomatic sub-types" of the three top-level error types, which MUST NOT replace them; §12's port addendum item 17 requires OAuthProtocolError specifically to be a sub-type of this class so existing catch (AuthError) call sites keep matching it unchanged — that backward compatibility is what makes contract 1.4 additive rather than breaking). Every OTHER pre-existing construction site (new AuthError(message)) is untouched and keeps compiling exactly as before.

Reason

An OPTIONAL, stable, machine-readable failure code. Populated only for a CONTRACT.md §12.4 ID-token validation failure, with one of the seven contract-fixed reason strings in IdTokenFailureReasons (§12 T1 reference judgment call 2: the reason code rides on this EXISTING AuthError type via this additive property, rather than a second error class). null for every other AuthError — including every pre-existing construction site and every OAuthProtocolError, which carries its own structured Error/ ErrorDescription pair instead.
