Remarks

An unknown value decodes to the enum's Unknown member rather than throwing (CONTRACT.md §27.11 rule 1). Throwing fails the whole response, so one field of one record the caller did not ask about would take down an entire page — including the records it did ask for.

It never silently maps to the zero member, which is the trap this used to avoid by throwing: reading "suspended" as whatever happens to be declared first would turn a new state into a wrong one, and on this surface those states gate access. Unknown is a state of its own, and its wire spelling is the empty string — which no server value is, so carrying an unrecognised value back into an update is refused by the server rather than written as a spelling it never used.

An enum with no Unknown member still throws, so this cannot quietly change behaviour for a hand-written enum that never opted in.
