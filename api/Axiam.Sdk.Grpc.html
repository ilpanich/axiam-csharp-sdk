Namespace Axiam.Sdk.Grpc

Classes

AuthInterceptor

Sync-safe authorization/x-tenant-id metadata injection on every outgoing gRPC call (CONTRACT.md §5), plus an UNAUTHENTICATED single-flight refresh-and-retry (§9, D-10) that drives the EXACT SAME shared RefreshGuard the REST transport uses — never a second guard instance.

AxiamGrpcAuthzClient

gRPC authorization transport (CONTRACT.md §1/§2/§5/§9, D-10). Wraps ONE long-lived GrpcChannel (via AxiamGrpcChannel — strict TLS, §6) intercepted by an AuthInterceptor that shares the EXACT SAME RefreshGuard/session AxiamClient's REST transport uses — never a second guard instance.

AxiamGrpcAuthzClient.AccessCheck

A single authorization check request item for BatchCheckAsync(IEnumerable<AccessCheck>, CancellationToken).

AxiamGrpcChannel

Constructs the SDK's ONE long-lived gRPC channel (D-10, CONTRACT.md §6) by reusing the EXACT SAME strict-TLS HttpClientHandler configuration the REST transport uses (CreatePrimaryHandler(byte[]?, byte[]?, byte[]?)) — additive customCa chain-trust honored, never a TLS-certificate-validation bypass. The channel is disposed by whichever component constructs it (Grpc/AxiamGrpcAuthzClient.cs), mirroring the Java sibling's AutoCloseable GrpcAuthzClient and Go's ClientConn ownership model.

RptPermission

A UMA 2.0 permission carried by an RPT (X2), from Permissions.

TokenCnf

The §10.3 sender-constraint, modelled once (RFC 8705 §3 / RFC 9449 §6). Both members are the raw proto3 string default ("") rather than null when unset on the wire — CONTRACT.md §1.1.1 rule 3 requires the distinction between "no cnf at all" (Cnf/Cnf itself null) and "a cnf naming neither method" (this record present with both members empty) to survive into the typed value.

TokenGrpcClient

validate_token/introspect_token (CONTRACT.md §1.1.1, §10.3, contract 1.51) — axiam.v1.TokenService. Built exactly like AxiamGrpcAuthzClient: the shared long-lived channel, the same AuthInterceptor the REST-sharing session uses, and UNAUTHENTICATED->single-flight-refresh->one-retry via the SAME RefreshGuard — never a second guard instance.

TokenIntrospection

axiam.v1.TokenService/IntrospectToken's typed response (CONTRACT.md §1.1.1 rule 3): the RFC 7662 field set, Cnf and Permissions/ ExtExchangeIss included.

TokenValidation

axiam.v1.TokenService/ValidateToken's typed response (CONTRACT.md §1.1.1 rule 3): every field the message defines, Cnf included.

UserInfo

The authenticated caller's OIDC-style identity claims, returned by GetUserInfoAsync(CancellationToken) (CONTRACT.md §1.1). The typed SDK-facing projection of the wire axiam.v1.GetUserInfoResponse — the low-latency gRPC counterpart of the server's REST GET /oauth2/userinfo endpoint.

TokenStatus

CONTRACT.md §10.3 rule 2's four-way answer to "is this token usable as presented?" — deliberately NOT reducible to valid/active alone (that is the whole point of §10.3): a caller that only checks the boolean has converted a sender-constrained token back into a bearer token.
